# Source architecture and review boundary

This standard-profile review covers Oiuhqw/sharex-mac at e8f95968852fc85900f98e6f966d348935f35192. At the start of this audit, worktree changes were documentation only. The product is a lightweight native macOS screenshot utility with eight capture modes, precision selection, annotation/redaction, clipboard delivery, optional local PNG saving, and native shortcut settings. ShareX is the product inspiration; local sources provide no comparable security-control baseline.

The interactive macOS user authorizes Screen Recording and operates capture/edit/export. Other applications supply visible pixels and window metadata through OS APIs. Same-user writers may control preferences or selected output directories; those rights alone do not establish a privilege violation. Screenshot recipients, clipboard consumers, filesystem readers, dependency publishers, and CI maintainers have distinct authority. Protected resources are captured pixels, redacted output, process memory, user files, and build/release integrity. There are no app accounts, tenants, runtime plugin loader, production network client/server, URL/document-open ingress, or webview found in App/Sources/App.swift and project.yml.

The app uses Swift 6, AppKit, SwiftUI settings, ScreenCaptureKit, CoreGraphics/CoreImage and Metal on macOS 14+. ShareXCore is a local Swift package. KeyboardShortcuts 3.1.0 is the only external runtime package, pinned by exact version and revision in project.yml and Package.resolved. Its cached source at .audit/KeyboardShortcuts-3.1.0 is an explicit read-only exception to the .audit exclusion. Xcode 26.3 and hash-pinned XcodeGen build the app. Base.xcconfig can include local signing configuration. GitHub workflows build and package an ad-hoc signed universal app with Hardened Runtime; source does not configure Apple notarization or App Sandbox.

CaptureCoordinator.swift serializes capture on the main actor, checks Permissions.swift, handles delay/cancellation, then calls ScreenCapture.swift. ScreenCaptureKit captures display/window pixels; fresh window-ID lookup and own-PID exclusion constrain selection. Display topology and cached shareable content influence targets. Imaging.swift checks pixel counts, arithmetic, actual storage and combined allocations. Native OS permission enforcement, window-ID lifetime and physical display behavior remain external facts.

SettingsStore.swift reads settings.v1 through ShareXCore Settings.swift. The decoder bounds data at 1 MiB, sanitizes styles/options and drops invalid last-region geometry. SettingsView.swift exposes native controls and directory selection. Hotkeys.swift registers eight commands and validates recorder conflicts. KeyboardShortcuts separately decodes stored preferences, handles Carbon events and translates keyboard layouts. Stored decoding is not the same path as recorder validation.

EditorView.swift accepts pointer, key, plain text and toolbar input. EditorDocument.swift holds editable state and undo history. Renderer.swift owns source images, bounded effect/live caches, protection intersections, sanitized effect inputs and opaque fallbacks. Preview, loupe, crop, undo/redo, final flattening and window closure can expose different copies. Export.swift composes PNG/TIFF from the final document. OverlayController.swift clears windows/resources and requests sharingType.none, which explicitly does not guarantee exclusion from other recorders.

ExportDelivery.swift independently tracks clipboard and file success and retains an encoded image during recovery. Export.swift resolves the selected absolute directory, handles default directory creation and symlinks, then uses non-overwriting writes with collision retries. Save As uses a user-approved native panel and atomic replacement. General clipboard disclosure and chosen local file storage are intended. Actual ACLs, concurrent directory writers and storage semantics must be established before alleging a cross-principal result.

Compile-gated E2E code accepts CLI modes, diagnostic paths, image fixtures and an AX subprocess request. E2ESettings.swift bounds request/reply data, uses an immediately unlinked temporary response file, binds the helper to its parent, limits AX traversal and guards synthetic input. App.swift excludes this driver without SHAREX_E2E. Packaging checks strings/symbols for test-code remnants. scripts/run-bounded.py limits time but is not an OS sandbox. Fuzz and formal sources are developer-only and remain within static inventory.

The supply boundary includes dependency resolution, downloaded XcodeGen, generated project files, optional local config, CI event inputs, artifacts, codesigning and DMG production. Workflows request contents:read and pin action revisions. Source cannot establish repository policy, runner isolation, real signing identity or installed permissions. Native CI is separate product verification, not evidence of sandboxed security execution.

No compatible prior coverage ledger/findings were found. This run starts current units without prior confirmed exclusions. Five companion domains apply: desktop/local IPC for files, native authority and test helpers; memory/binary for image buffers and Carbon/AX FFI; resource exhaustion for allocation, caches, parsing and lifecycle; supply chain/release for builds and packaging; data lifecycle for redaction, derived pixels, undo, export and diagnostics. Absent web, cloud, model, broker and tenant services do not create hypothetical surfaces.

All audit work is source-only on Windows with PowerShell. WSL is prohibited. No approved OS sandbox enforces the complete required network, environment, filesystem and resource limits, so hunters/verifiers must not execute target code, tests, fixtures or fuzzers, fetch dependencies, dispatch CI or probe services. No artifact promotion is authorized. Source checks use artifact:null. The previously denied full fuzz campaign must not be retried. Only a concrete source-grounded boundary hypothesis can become needs_validation; an unavailable runtime alone is not a vulnerability.
