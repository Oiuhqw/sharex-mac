# First noisy capture sink comparison

This branch tests whether the current recording's writer or source-sample retention is necessary for its startup gap. It is a diagnostic branch. It does not implement a recording fix or pass production E2E.

Dispatch `agent-capture.yml` on this branch with `frame_gap_replay=true`. The existing input now runs `scripts/frame-gap-startup.py`. The workflow builds with `FRAME_GAP_PROBE`, runs the original setup UI once, enables agent access, then collects control, metadata, metadata, control on one Mac. Each arm starts fresh app and fixture processes. Later arms reuse the setup account state. Setup is not repeated, and no maintenance, uninstall, or app replacement runs between arms.

Each arm executes the original native `Run.stories` until its first noisy byte-limit capture. The driver checks all 15 prefix steps, seven movie decodes and four PNG decodes in order. The final predecessor remains the three-second region capture and inline decode. Previous writers keep their normal lifetimes. The app selects the diagnostic sink only for the exact request UUID and the expected 1 MiB, 30-second, 15 FPS window request after seven writer constructions and completions. BGRA, queue depth three and the heartbeat remain fixed.

The metadata sink does not construct a writer, read or copy pixels, or retain samples. It records scalar callback metadata and acknowledges the first complete frame with zero accepted encoder frames. After three seconds, it stops the stream, flushes the trace and returns explicit incomplete media with `diagnostic_metadata_complete`. It creates no movie. The control runs the original byte-limit completion and independent decoder with the unchanged 500 ms frame-gap gate. Both arms use the original MCP start and CLI status polling, including the 100 ms wait after each response.

`frame-gap-startup-out/comparison.json` records every arm, original results, first PTS and displayTime intervals, all source intervals, first-second callbacks, fixture draws, heartbeats, predecessor decoder exit timing and status launch times. Per-arm directories retain raw traces, fixture operation traces, movies, manifests and command logs. Failed control decodes remain failed. Collection continues through all four arms. Missing traces, overflow, stream errors, unexpected writer counts or fabricated metadata media make collection incomplete.

The control acknowledges after its first append. Metadata acknowledges after its first complete callback. Removing append time changes subsequent status launch timing. A control-only gap therefore supports downstream influence but does not isolate the encoder from this timing change. A metadata gap rules out this capture's writer and retained sample as necessary causes. It leaves earlier encoder and decoder state in the experiment. Two observations per arm cannot establish a failure rate.

The local contract suite verifies routing, prefix order, inherited target discovery, polling cadence, negative evidence and balanced continuation. Native compilation and this four-arm Mac experiment must run before interpreting results. A production fix still requires the complete original E2E workflow.
